# 핀랩풋볼(Finlab Football) 독립 관리자 시스템(Admin Backoffice) 기능 정의서

본 문서는 **핀랩풋볼(FINSS_OJT)** 서비스의 핵심 비즈니스 도메인(풋살 소셜 매칭, 구장 대관, 매니저 권한, 커뮤니티, XML 일정 관리 등)을 독립된 별도 관리자 서버(Admin Server)로 분리 구축할 때 필요한 기능 요구사항 및 세부 스펙을 정의합니다.

---

## 1. 시스템 개요 및 목적
- **목적**: 메인 사용자 서비스와 운영 관리자 시스템을 물리적/논리적으로 분리하여 보안성 강화, 시스템 안정성 확보 및 효율적인 백오피스 운영 제공
- **주요 대상**: 백엔드 시스템 관리자, 구장 운영팀, CS 담당자

---

## 2. 세부 기능 명세

### 2.1 👥 회원 및 매니저(GM) 관리 (User & Manager Administration)
- **전체 회원 목록 및 상세 정보 조회**
  - 회원 검색 기능 (아이디, 사용자 이름, 이메일, 전화번호, 가입 기간)
  - 회원 상태 제재 관리 (정상 / 일시 정지 / 영구 제재 / 탈퇴 처리)
  - 회원별 매치 참가 이력, 게시글 작성 이력 모니터링
- **구장 매니저(GM) 자격 승인 및 관리**
  - 일반 회원의 매니저 신청서 검토 및 승인/거절 기능 (`is_manager = 1` 승격)
  - 매니저별 담당 구장 배정 및 배정 해제 관리
  - 매니저 활동 내역 및 운영 실적 조회
- **매너 점수 및 노쇼(No-Show) 제재 시스템**
  - 참가자의 굿매너/비매너 신고 내역 확인 및 매너 점수 조정
  - 무단 불참(노쇼) 횟수 집계 및 자동 매치 신청 제한(예: 14일 정지) 조치

---

### 2.2 🏟️ 구장 및 대관 일정 관리 (Ground & Schedule Management)
- **신규 구장 검수 및 승인 관리**
  - 구장 관리자가 신청한 신규 구장 정보(구장명, 주소, 시간당 가격, 실내외 여부, 잔디 종류, 주차/조명/샤워실 등 옵션) 검수 및 등록 승인
  - 구장 정보 변경 요청 승인/반려 및 구장 폐업/비활성화 처리
- **구장 일정 XML 및 슬롯 동기화 관리**
  - `ground_schedules.xml` 파일 관리, 서버 동기화 및 XML 파싱 상태 모니터링
  - 구장별 대관 가능 타임슬롯 생성, 수정 및 정기 휴무일 일괄 설정
  - XPath 기반 구장 검색 성능 및 XML 데이터 무결성 검증

---

### 2.3 ⚽ 소셜 매치 및 경기 운영 관리 (Social Match Operations)
- **실시간 매치 상태 모니터링 및 제어**
  - 매치별 모집 인원 현황(신청 가능 / 마감 / 인원 미달) 실시간 모니터링
  - 우천, 기상 악화, 최소 인원 미달 시 **매치 일괄 취소 및 알림 발송**
- **경기 하이라이트 영상 및 미디어 파일 관리**
  - 매치 종료 후 하이라이트 동영상 파일 업로드, 썸네일 등록 및 다운로드 링크 관리
  - 미디어 스토리지 용량 감시 및 오래된 영상 파일 아카이빙/삭제
- **전담 매니저 배정 및 경기 현황 체크인**
  - 매치별 현장 진행 매니저 배정 관리
  - 매치 시작/종료 처리 및 현장 노쇼/부상 발생 건 보고서 접수

---

### 2.4 📋 커뮤니티 컨텐츠 및 스토리지 관리 (Content & Storage Management)
- **게시글 및 댓글 모니터링**
  - 부적절한 게시글(스팸, 욕설, 타인 비방, 광고성 등) 강제 숨김(블라인드) 및 삭제
  - 작성자 계정 제재 연동
- **첨부파일 및 물리 스토리지 관리**
  - `uploads/` 디렉토리 내 게시판 첨부파일, 유저 프로필 이미지, 매니저 지원서 용량 모니터링
  - DB와 연결이 끊어진 더미 파일(Orphaned Files) 주기적 Cleanup 기능

---

## 3. 보안 및 권한 제어 요구사항
1. **역할 기반 접근 제어 (RBAC)**: 슈퍼 관리자(Super Admin), 구장 관리자(Ground Admin), CS 담당자(CS Admin) 등 권한 등급 세분화
2. **이중 인증 (2FA)**: 관리자 로그인 시 이메일 또는 OTP 인증 추가
3. **독립된 DB / REST API 연동**: 메인 웹 서버와 관리자 서버 간 보안 토큰(JWT / API Key) 기반 비동기 통신
